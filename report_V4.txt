## 怀疑点 5：首轮提醒 vs nudge 循环提醒的状态/逻辑重叠

- **文件:行**：`injection.py:34-48`（`_NudgeCounter`）、`:77-115`（forward 两分支）；`nudge.py:22-29`（`should_nudge`）、`:32-35`（`nudge_reminder`）
- **怀疑理由**：两条提醒可能各自维护状态，或在同一 boundary 重复注入；`should_nudge` 可能是被 injection 内联规则取代的残留
- **调查过程**：
  - **状态**：唯一状态是 `injection.py:34` 的 `_NudgeCounter`；`nudge.py` 全是无状态纯函数 → **无状态重复**。
  - **逻辑**：`spoke` 每 boundary 只扫描一次（`:86-88`），同时驱动 `spoke_yet` 与 `rounds` 归零；首轮分支 `:95-107` 命中直接 `return`，周期分支 `:109-115` 不会执行 → 同一 boundary 不会双注入（首轮条件含 `not message.content`，与 `RuntimeReminderModule`/envelope 的"先占位"约定一致；`tests/test_realtime_first_speak_nudge.py:62-73` 覆盖）。
  - **规则重复**：`nudge.py:22 should_nudge()` 的 `rounds_since_speak >= interval` 与 `injection.py:109` 内联的 `rounds % interval == 0` 等价，但 injection 未调用它；`rg "should_nudge" -g '*.py'` 只有 `nudge.py:22` 定义与 `:42` `__all__` 自引用，**零调用点** → 确认无用。
  - **实测耦合（非死代码，仅报告）**：`:81-84` 切换 `turn_id` 时只重置 `first_result_seen`/`spoke_yet`，**不重置 `rounds`**。用 `uv run python` 跑真实模块：turn1 连续 4 个 boundary 后，turn2 首个 boundary 若已带 envelope（`content` 非空，首轮分支被跳过），会立即追加 *"You have not spoken to the user for 5 tool rounds"*。若这是"距上次 speak 的累计轮数"的有意语义则无误，否则首轮提醒与周期提醒存在跨 turn 状态耦合。
  - 相关测试：`tests/test_realtime_first_speak_nudge.py`、`tests/test_realtime_supersede.py` 共 13 项，与 `test_task_message.py`、`test_fork_context.py` 一起运行全部通过（13 passed），证明上述活跃路径当前成立。
- **结论**：两模块**无状态重复**，逻辑重叠但互补；`should_nudge` 是**确认无用**的重复规则实现。
